# 2026-07-30 multi-tab(主窗口多标签页)

## 起因

用户要求主窗口支持多 Tab:把「当前打开的 session」摊开成顶部一条可点的 tab 条,点 tab 切换 = 等价于侧栏单选切换,关 tab = 清该 session 的前端缓存(不删 DB、不删侧栏)。核心诉求是「同时开多个会话、一键切换,不必每次回侧栏找」。经多轮讨论(误以为要做 tag、再做 tab 的产品判断)后用户拍板:做,MVP 默认值已定。

## 设计(基于代码事实,关键决策)

### 三条决定打法的事实

1. **「打开 session」已有唯一入口**:`openSession(sessionId, projectId?)`(`App.tsx`)做 `ChatService.OpenSession` → 加载历史 → seed 缓存 → `setSelectedSessionId`。侧栏点击、popout 启动全都走它。**「打开一个 tab」= 在 `openSession` 里多记一笔,不新逻辑。**

2. **per-session 缓存清理已有集中函数 `purgeSessionState`**,但它把「清 24 个缓存 map」和「从侧栏删 session」绑在一起——后者是硬删除语义。**关 tab 要前者不要后者**(关 tab ≠ 删会话,DB 还在),所以拆出 `evictSessionCache`(纯清缓存,不动侧栏、不动选中),`purgeSessionState` 改为 `evictSessionCache` + 删侧栏 + 清选中。这是 §5.3「最好的修复常是减代码」——把已有代码拆开复用,不新写一大段 eviction。

3. **File/SCM 面板天然 per-tab**:SidePanel 读的全是 `xxxBySession[selectedSessionId]` 切片(`branchBySession`、`mergeableBySession`、`sessionChanges`、`worktreePath`…)。tab 切换 = `selectedSessionId` 指针变 = SidePanel 自动跟着读新桶。**没有「为每个 tab 复制一份 SidePanel」的工作量**,组件树单实例靠指针选当前桶。

### 布局:tab 条横跨主区顶部,右侧 SidePanel 独立常驻列

- tab 条活在 `<Panel id="main">` 内、`<main>` 之前(包了一层 `.main-col` flex column 容器给 tab 条一行 + main 填剩余)。
- SidePanel 是 `<Panel id="side">`,与 main 平级的第三列,**永远在窗口最右侧那一整列,不随 tab 动,不被 tab 条覆盖**。这是 VS Code / 浏览器 + 侧栏的模型。

### tab 多了自动缩小(不超 ChatView 宽度,浏览器策略)

- `.tabbar-tab` 用 `flex: 0 1 auto; min-width: 90px; max-width: 190px`——不增长、可缩小、自然宽度为基。tab 多了每个往下压(到 min-width 为止),**条带不超出主列宽度**。
- `.tabbar-tab-title` 用 `flex: 1 1 auto; min-width: 0`——压缩时标题先让位(省略号),状态点 + 关闭按钮 `flex-shrink: 0` 保固定尺寸。
- 这是浏览器 tab 条的标准策略(等分直到 min-width)。

### 横向滚动条:hover 才出现的 overlay 滑块(独立 lane + 可见配色)

**演进(踩了两次)**:

1. **初版**:`::-webkit-scrollbar { height: 0 }` 把横向滚动条**完全藏掉**(只剩滚轮 + 拖拽)。用户反馈想要「位置像原生、不占空间、只 hover 出现的细滚动条」。
2. **第二版**(overlay thumb 透明↔实色 toggle):用固定预留 7px height + 透明 track + thumb `transparent`→`--sep-strong` toggle。**但用户反馈 hover 时滑块还是看不见、选不中**——「似乎响应了但层级不对」。
3. **根因(本轮修)**:不是层级问题,是**几何 + 配色**双重问题:
   - **几何**:scrollbar lane(底部 7px)与 tab 底边(25px tab 在 34px 条带居中,跨 ~4.5–29.5px)**重叠**(27–29.5px 区段),还被 `.tabbar` 的 `border-bottom` 进一步挤压。滑块画在 tab 背景之上但贴着 tab 圆角底边,几乎无独立可点区。
   - **配色**:thumb 用 `--sep-strong`(`rgba(255,255,255,0.11)`)——深底上几乎不可见;再加 `border: 2px transparent + background-clip: padding-box` 把有效厚度削到 **3px**,更糊。
4. **最终修法**(`index.css` `.tabbar-scroll`):
   - `.tabbar-scroll` 加 `padding-bottom: 7px`——**给滑块一条独立的、不与 tab 重叠的底部 lane**。`.tabbar` height 固定 34px(不是 min-height),padding 在 34px 框内消化,**不抬条带高度、不产生 hover 抖动**(padding 始终预留,只是 thumb 颜色 toggle)。
   - thumb 配色改用**真可见**的前景色:`transparent`(空闲)→ `var(--text-3)`(strip hover)→ `var(--text-2)`(thumb 自身 hover)。弃用 `--sep-strong`(太浅)。
   - 去掉 `border: 2px transparent + background-clip: padding-box`(那是把滑块削薄到 3px 的元凶)——现在滑块是完整 7px 厚、`border-radius: 4px`,既清楚又好点。
   - 仍保留 WebKit 陷阱的防范:height **不在 hover 切换**(只在 thumb 背景 toggle),避免 hover 进出抖动。
- Firefox:`scrollbar-width: none`(overlay 滚动条跨引擎不可靠主题化,Firefox 上仍靠滚轮 + 拖拽滚动)。
- 滚轮 + 拖拽滚动无论滑块显不显都正常工作。

### 状态:`openTabs` 显式 state(不派生)

- `const [openTabs, setOpenTabs] = useState<string[]>([])`。**不从缓存 map key 派生**(如 `Object.keys(itemsBySession)`)——内存优化器切走会丢非活跃 session 的 items 缓存,派生会让 tab「消失」。tab 语义 = 「用户打开过、还没关」,与缓存是否在内存无关。§5.3 尊重数据源,不靠启发式。
- 活跃指针复用现有 `selectedSessionId`,**不另存 activeTabIndex**(避免两套真相)。`openTabsRef` 供 `closeTab` 读「邻居」选下一个 tab,不进依赖避免重建回调。

### tab ↔ popout 互斥

- 一个 session 要么是主窗口的一个 tab,要么被 popout 成独立窗口,**不同时**。
- `popoutSession` 顺手 `setOpenTabs(filter)` 把它移出 tab 条;`poppedSessionIds` 守卫也过滤一次(双保险)。
- tab 右键「移到独立窗口」复用 `popoutSession`。
- 关 popout 窗口 → `chat:popout-changed false` → **自动恢复成 tab**:`chat:popout-changed` handler 在 `popped=false` 时 `setOpenTabs((prev) => prev.includes(id) ? prev : [...prev, id])`。这等价于「关 popout 回主窗口」的旧恢复路径(popout 窗口一关,主窗口恢复对该 session 的渲染/事件处理),只是顺带把它登记回 tab 条,让它可见而非藏在侧栏。

### 关 tab:邻居选中 + 「正在生成」拦截确认框

- `closeTab` 调 `evictSessionCache`(纯清缓存,不删侧栏、不删 DB;`evictSessionCache` 也顺手把 id 从 `openTabs` 移除——单一 choke point)。
- 关的是当前 tab 时:取邻居(next,else prev)→ `openSession` 切过去;无邻居 → `setSelectedSessionId(null)` 回空态。
- 中键关闭(`onAuxClick button===1`)照浏览器/VS Code 习惯。
- **⌘W / Ctrl+W 关当前 tab**(浏览器/VS Code 习惯):全局 keydown listener,主窗口专属(popout 窗口无 tab 条,⌘W 保留原生「关窗口」语义)。覆盖 Wails3/macOS 默认的「⌘W 关整个窗口」。无选中时 no-op。复用 `closeTab`,定义在 `closeTab` 之后(避免 used-before-declaration)。
- **正在生成(prompting)的 tab 关闭拦截**:关一个 `statusBySession[id] === "prompting"` 的 tab 不是单纯清缓存——后端 turn 还在跑,静默关掉会丢失「这 tab 在输出」的可见性。`closeTab` 在此情况下**先弹 `CloseTabDialog`**(三选一):
  - **取消**:什么都不做(tab 保留,turn 继续)。
  - **仅关闭标签页(detach)**:只 evict 前端缓存、移出 tab 条;turn **不停**,后台继续跑,输出照常落 SQLite(重开该 session 可见)。等价「只关窗口不停止输出」。
  - **停止并关闭(stop)**:先 `stopSessionById(id)`(`StopSession` 取消 turn)再 evict。
  - idle / error / closed 状态**直接关**,不弹框(无歧义)。
  - 为支持「关非当前 tab」也走 stop,把 `stopSession` 抽出 `stopSessionById(sid)`(显式 sid,不写死 selectedSessionId);composer 的 Stop 按钮 = `stopSessionById(selectedSessionId)`。

## MVP 产品决策(已落地,可推翻)

1. 关 popout 后**自动**恢复成 tab(等价旧 popout 回主窗口的恢复路径,顺带登记进 tab 条让它可见)。
2. 关 tab:**点击 ×、中键、⌘W/Ctrl+W** 三路。⌘W 覆盖 Wails3/macOS 原生「关窗口」。
3. tab 顺序 = 打开顺序,**不可拖拽重排**(v2)。
4. tab 显示仅 session.title;hover tooltip 显示 `title · projectName`(跨项目区分)。
5. tab 多了**自动缩小到 min-width**(浏览器策略),不超主列宽度、不换行。
6. **关正在生成(prompting)的 tab 弹确认框**:取消 / 仅关闭标签页(turn 后台继续)/ 停止并关闭。idle/error/closed 直接关。
7. **横向滚动条**:hover 才显的细 overlay 滑块(不占垂直空间),空闲完全看不见。

## 补充修复(review 后,2026-07-30,接手者)

代码 review 后两处修复:

### 1. 横向滚动条一直不显示 —— 真根因:`scrollbar-width: none`(标准属性被现代 Chromium 执行)

- **现象**:tab 很多时该出横向滚动条,但任何情况下都不显示。
- **排查过程(两次,第一次错)**:
  1. 第一次猜全局 `::-webkit-scrollbar { display:none }`(`index.css:1320`)没被覆盖 → 给 `.tabbar-scroll::-webkit-scrollbar` 补 `display:block`。**必要但不充分**——实测仍不显示。
  2. 用浏览器(Chromium 150)搭最小复现:同结构 + 全局隐藏规则,跑「buggy(`scrollbar-width:none` + 透明 hover thumb)」vs「fixed(`scrollbar-width:thin` + 常显 thumb)」。两变体都溢出(scrollWidth 1034 > clientWidth 620);`getComputedStyle().scrollbarWidth` 分别 `none` / `thin`。
- **真根因**:`.tabbar-scroll { scrollbar-width: none }`(旧 `index.css:2217`)。**标准 `scrollbar-width` 属性被现代 Chromium(WebView2/Win、Chrome 121+)及越来越多 WKWebView 执行**——`none` =「不画滚动条」,且**使 `::-webkit-scrollbar` 自定义样式在这些引擎上失效**。旧注释误以为它只影响 Firefox。所以无论 `::-webkit-scrollbar` 怎么设(display:block/height/thumb)都被 `scrollbar-width:none` 一票否决。叠加次因:thumb 默认 `transparent`、仅 `:hover` 显——即便在忽略 `scrollbar-width` 的引擎上,不 hover 也不显。(已核实 Wails3 drag `@wailsio/runtime/dist/drag.js` 只在 dragging/resizing 时吞事件、不挡 `:hover`,故 drag 区不是主因。)
- **改法**(对齐同仓已验证可用的 `.cv-scroll`):`.tabbar-scroll` 改 `scrollbar-width: thin` + 加 `scrollbar-color: var(--text-3) transparent`(特异性盖过全局 `* { scrollbar-width:none }`);thumb 由 `transparent` 改常显 `var(--text-3)`(不再 hover-gated,hover 时 `--text-2`)。`::-webkit-scrollbar { display:block }` 保留(给忽略标准属性的 Safari/旧 WKWebView)。即「标准属性 + `::-webkit-scrollbar`」双机制跨引擎都能显——与 `.cv-scroll` 同策略。
- **取舍**:牺牲「仅 hover 显」的 overlay 美学,换「任何引擎稳定可见」。hover-only 在走标准属性的引擎上做不到(标准属性不支持 hover 显隐),且之前正是它导致看起来永久消失;常显更可发现,可接受。
- **次要点(未改,仅记录)**:`.tabbar-scroll` 自身没设 `--wails-draggable: no-drag`,处在 `.tabbar` drag 区内;**手动拖滑块**可能被窗口拖拽吃掉(滚轮不受影响)。若实测拖不动滑块再给 `.tabbar-scroll` 补 no-drag。
- **改了哪些文件(滚动条)**:`index.css`(`.tabbar-scroll` 滚动条规则重写)。

### 2. 非激活 tab 任务完成时显示未读小蓝点

- **需求**:某 tab 的回合结束、且它不是当前激活 tab 时,在该 tab 上显示未读提示(等价侧栏 session 行尾部的小蓝点)。
- **实现(复用既有数据源,零新 state / 零后端)**:
  - `unreadBySession` 本就是「回合结束(idle)且非选中 session → 标未读」(`App.tsx` chat:status handler,~518 行),`openSession` 时清(~713 行)。直接喂给 tab。
  - `TabBarTab` 加 `unread: boolean`;`App.tsx` 渲染 tab 时传 `unread: !!unreadBySession[id]`。
  - `TabBar.tsx`:当 `tab.unread && tab.id !== activeId` 渲染 `<span className="unread-dot">`(复用全局 `.unread-dot` = `var(--accent)` 蓝 7px,与侧栏同款;tooltip 复用 `sidebar.unreadTip`)。点该 tab → `openSession` 清未读 → 蓝点消失。
- **改了哪些文件(未读蓝点)**:`TabBar.tsx`(unread 字段 + 蓝点渲染)、`App.tsx`(tabs 映射传 unread)。
