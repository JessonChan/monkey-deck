## 设计(关键决策)

- **STT 不是 agent 通道**:whisper.cpp 的 `whisper-server` 是宿主自己拥有的本地子进程,与 §1.1 的
  「agent 只走 ACP」无关(那条约束管 agent harness)。复用 harness 的进程纪律(§3.2):Setpgid 独立进程组 +
  整组 SIGTERM→SIGKILL 回收 + watcher 独占 `cmd.Wait`(无双 Wait 竞态);whisper-server 不 fork 子进程,
  不需要逃逸 reap 层。
- **sidecar 生命周期 = 懒启动 + 自愈**:首次 `Transcribe` 才 spawn(不用 STT 零资源占用);就绪判定 =
  轮询 `/health`(大模型加载秒级,预算 30s,测试可注短值);进程死了/换模型 → 下次 Transcribe 自动重启。
  换模型/换 server 路径 = 停掉现有 + 懒重启(不 eager spawn)。并发 Transcribe 经 `s.mu` 串行化 ——
  并发调用方排队等同一个 sidecar 起来后共用(单飞,已测)。
- **server 二进制发现**:`MD_WHISPER_SERVER` 环境变量 > 持久化自定义路径(`stt.server_path`)>
  PATH 探测(`whisper-server`)。PATH 探测前先 `shellenv.Resolve` 补登录 shell PATH —— Finder 双击启动
  PATH 贫瘠的已知坑(§5.4 #8)同样命中 brew 安装的 whisper-cpp。测试经 `discoverFn` 注入 stub 保证确定性
  (对齐 chat 的 `spawnFn` 注入模式)。
- **模型管理**:ggerganov/whisper.cpp 的 ggml 工件,策展 9 个目录项(英文 q5_1 族 + large-v3-turbo 族 +
  多语言族)。模型是**可再生缓存** → 落 `CachesDir/stt-models`(config 语义:DataDir 只放不可再生数据)。
  下载流式写 `.part` + 原子 rename(杀进程不留半截模型文件);`Content-Length` 短读校验;进度事件
  `stt:progress` 节流 1MiB 一发;`downMu` 串行化并发下载。默认选型 `base.en-q5_1`(57MB,听写够用);
  删除选中的模型被拒(ErrModelInUse,须先切走)。**SizeBytes 是近似值(仅展示/进度),就绪判定只看文件存在**。
- **持久化**:选中模型 + 自定义 server 路径存 `settings` KV 表(SQLite 单一真相,§1.5),经 `store` 包
  (§2.1 不写裸 SQL)。stt service **自开一个 `store.New(同一 DBPath)`**:WAL + busy_timeout 串行化
  稀有配置写,免去跨 service 传 store 实例的构造耦合(迁移幂等,启动顺序串行)。
- **binding 面**(`internal/stt.Service`,已注册为第 3 个 Wails3 service):
  `TranscribeAudio(audioB64, mime)`(前端走 base64,对齐 Composer 图片附件惯例)、`Transcribe(ctx, audio, mime)`
  (核心管道,兼 `remote.Transcriber`)、`STTStatus`、`ListSTTModels`、`SetSTTModel`、`DownloadSTTModel`、
  `DeleteSTTModel`、`SetSTTServerPath`、`StopSTTSidecar`。
- **/api/stt**(内嵌远程服务新增端点):远程浏览器/PWA 客户端不走 webview binding,直接
  `POST /api/stt`(raw body `audio/*` 或 multipart `file` 字段)→ `{"text": "..."}`。**走既有鉴权墙**
  (cookie/bearer,不在豁免清单)。multipart part 无 Content-Type 或为通用 `application/octet-stream` 时按
  文件名后缀推 mime(浏览器 FormData 的常见形态)。`ErrServerNotFound`/`ErrNoModel` → 503,其它 → 500。
  这是 §1.8「不自建第二套 API」的一次**任务指定的扩展**(音频 blob 直传的天然形态),已在 remote 包文档标注。
- **尺寸/超时纪律**:单次音频 ≤ 25MB;`/inference` 往返 ≤ 2min(大模型慢于实时);下载无超时(跟随
  binding 调用的 ctx);`/health` 就绪预算 30s。

## 假二进制单测(§5.1 落地)

`internal/stt/testdata/fakewhisper/main.go`:测试内 `go build` 编译出的假 whisper-server,
实现 `/health` + `/inference`(multipart),transcript 编码 `fake:<模型文件名>:<音频字节数>:<上传文件名>`
—— 一条字符串断言同时覆盖模型选择、字节透传、MIME→扩展名映射。信号量类测试用 `syscall.Kill` 的均
`runtime.GOOS == windows` skip(与 acp 包既有做法一致)。

覆盖:全管道转写 / sidecar 复用 / base64 入口 / 校验拒绝(空/非 audio/超限)/ 无模型、无 server 哨兵错误 /
换模型懒重启 + 持久化恢复 / 杀进程自愈 / 显式停(进程组 ESRCH 实证)/ `/usr/bin/false` 就绪超时且不泄漏
sidecar / 状态与列表 flags / 删除规则 / server 路径校验持久化清空 / 6 路并发单飞 / extForMIME 表 /
下载(成功 + 进度收口 + 幂等 + 404 清理 + 未知 id)/ 目录不变量 / remote 端点(鉴权墙 + raw + multipart +
405/400/413 语义 + 错误映射 + mime 后缀推断)。
