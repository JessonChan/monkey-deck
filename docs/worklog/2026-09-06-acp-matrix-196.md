- **tier-1 = spawn + Initialize**,复用探针既有管线的同一套原语:
  `NewRunner(cmd, nil)` + `NewHandler(workDir, …)` + `runner.spawnAndInit()`,
  每 RPC 硬超时 `probeInitTimeout = 20s`(与 `probe.go` 既有常量一致)。
  **不发 NewSession、不发 Prompt——零模型配额消耗**。
- 探针以临时文件 `internal/acp/probe_matrix196_test.go`
  (`go:build integration`,沿 `probe_integration_test.go` 形态)实跑,
  **跑完即删、不入库**——最终 diff 仅本 worklog 文件。
- 失败原文全量入档(不截断)。
- **入口命令来源**(按 monkey-deck 实际会 spawn 的规范形):
  - 内置 `Supported`:omp / opencode(`internal/harness/harness.go`);
  - 用户 harness 表(`Monkey Deck/monkey-deck.db` 的 `user_harnesses`,
    2026-09-06 实查):codebuddy `codebuddy --acp`、reasonix `reasonix acp`、
    codex-acp `codex-acp`(裸命令,Zed adapter 形);
  - KnownCatalog(#187 约定 `<BinaryName> acp`):claude(catalog id
    `claude-agent`)、codex(catalog id `codex-cli`);
  - 其余无登记项(mimo/chelper/dsnix/ark-helper/lark-cli/ocr/pinchtab/

- **图标判据**:`assets/harness-icons/<id>.<ext>` 存在性(svg/png;<id> 为

## 结论(阶段二/三输入)

**总判定:17 项中 7 项 tier-1(spawn+Initialize)可用,10 项不可用。**

### ACP 可用(7 项)

| harness | 入口命令 | 自报 agent | 备注 |
|---|---|---|---|
| omp | `omp acp` | oh-my-pi | 内置 |
| opencode | `opencode acp` | OpenCode | 内置 |
| opencode2 | `opencode2 acp` | OpenCode | 新包(@opencode-ai/cli),与 opencode 同族 |
| mimo | `mimo acp` | OpenCode | opencode 衍生 |
| codebuddy | `codebuddy --acp` | (空,省略 agentInfo) | 参数形是 `--acp` 非 `acp` |
| reasonix | `reasonix acp` | reasonix | 与 dsnix 同包(dsnix bin 已悬空) |
| codex-acp | `codex-acp` | @agentclientprotocol/codex-acp | 裸命令(Zed adapter 形);codex 本体不可直接 ACP |

### 不可用(10 项,三类失败形态)

1. **立即退出(peer disconnected before response,6 项)**:codex、lark-cli、ocr、
   pinchtab、shopify、uipro —— `acp` 不是这些 CLI 的子命令,进程秒退;属
   「非 ACP agent」,无降级空间(§1.1 纯 ACP 红线下不补 CLI 解析通道)。
2. **挂起型(20s 硬超时,3 项)**:claude、chelper、ark-helper —— 进程活着但
   initialize 永不响应(疑似 `<bin> acp` 进了各自交互/长驻模式)。⚠ 阶段二
   灰态设计需区分「立即失败」与「挂起」两种不可用形态;挂起型若存在专用
   ACP adapter 入口(如 claude 系),另行验证后单列,本卡不猜。
3. **二进制缺失(1 项)**:dsnix —— `~/.bun/bin/dsnix` 悬空软链(reasonix 包
   2026-08-01 更新后旧入口已删),非 harness 问题;清理悬挂 bin 即可。

  3. 用户 harness id `codebuddy` 无图标,而 catalog 图标名是

- 其余 13 项无图标(走 lucide Bot 兜底,既有约定降级,不报错)。

### 阶段二设计要点(实测反推)

- **入口命令不能统一假定 `<bin> acp`**:可用 7 项里已有三种形态
  (`acp` / `--acp` / 裸命令),ACPCommand 解耦必须按 harness 各自规范形,
  用户 harness 表的 command 字段即事实源。
- protocol 全部 =1;agent 自报名全部可取(codebuddy 空名走既有 agentInfo
  可选兜底,见 `probe.go` displayName)。
- initialize 成本极低(93ms–1.6s,超时项除外),灰态探测可低开销在线做。
