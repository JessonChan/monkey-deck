# #172 fork 徽章(Task #28914)

**日期**:2026-08-31
**状态**:完成(纯可见性卡片,XS)
**上游**:#172 Phase 2 fork 链路已落库(0023 migration / `SetSessionForkedFrom`),本卡只做消费端可见性

## 起因

fork 出来的 session 与原生 session 在侧栏行里没有任何视觉区分——`forkedFrom` 血缘只存在于 DB,用户分叉后认不出哪个是分叉。本卡给带 `forked_from` 的 session 行标题旁渲染 GitFork 小徽章,tooltip 告诉用户「分叉自哪个会话」。

## 改法

- **数据源**:`s.forkedFrom`(Go `store.Session.ForkedFrom`,`json:"forkedFrom,omitempty"` 已在库)。前端 bindings 本就含该字段,只需 `wails3 generate bindings` 重生成本地中间产物(bindings 不入库,gitignore)。`undefined`(omitempty 天然)与空串都视为「原生会话」,不渲染。
- **源标题解析**:`Sidebar` 内新增 `forkSrcTitleById` memo——对既有 `sessionsByProject` **全量**映射(跨项目)做 id → `customTitle || title` 查表,与 `allSessionIds` 同款派生方式、同依赖。tooltip 取「分叉自 {{src}}」;源会话解析不到(已删除/跨窗口快照滞后)回退源 id 前 8 位(JS `slice` 天然安全切片)。
- **位置**:`session-item-main` 内 **HarnessIcon 之后、pinned 之前**(label → renamedMark #154 槽位 → popped → HarnessIcon → **fork 徽章** → pinned → terminal → scheduled/perm/unread/draft 尾注)。#154 槽位逻辑、pin/闹钟守卫一行未动;fork 业务链路(ForkSession/门控/分叉动作)零触碰。
- **样式**:新增 `.session-fork-mark`,逐字镜像 `.session-renamed` 持久标记族(`flex-shrink:0; display:inline-flex;` + svg 色 text-3 安静档)——保 12px 行高纪律,行高零变化。
- **i18n**:`sidebar.forkedFromTip` = zh「分叉自 {{src}}」/ en「Forked from {{src}}」,zh/en 同步。
- **图标**:lucide `GitFork` size 12(Sidebar.tsx 既有 import,#172 Phase 2 菜单项已用),与 pin(11)/HarnessIcon(12)/terminal(12) 同族。
