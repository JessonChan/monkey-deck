# 2026-08-24 AGENTS.md 新增前端三端覆盖硬约束(§4.7/§5.6)

## 起因

M2 之后同一份 React 前端有了三张脸:桌面 GUI(Wails3 webview)、远程浏览器(§1.8 内嵌远程服务)、PWA(移动端)。三端并存的验证方法此前散落在各条 worklog 里(M2 的像素 diff、PWA 六件套的双视口 E2E),是「当次做法」而非全局纪律——某端定向改动漏回归另两端的风险随三端并存放大。用户拍板:把规则写进 AGENTS.md,对所有研发者 / AI agent 生效:**前端改动必须三端覆盖并确认;后端能力验证统一做一次;三端要有清晰的测试认知;单端定向改动回测时也必须考虑另两端不回归**。

## 改法(改了哪些文件)

- `AGENTS.md`(纯追加编号,不动既有小节):
  - **新增 §4.7「前端改动三端覆盖(硬约束)」**:定义三端各自的差异维度(引擎 / pointer / 视口断点 / 宿主能力 / 事件通道);任何触及 `frontend/` 的改动三端都要验、结果都要确认;单端定向改动必须显式确认另两端不回归(M2「桌面 UI 零修改 + 像素 diff=0」即既有实例);后端(Go/binding/协议)能力统一验一次,三端只确认本端通道;worklog 验证小节必须写清三端结果。
  - **新增 §5.6「三端验证矩阵」**:每端一行「启动方式 × 本端必测维度(别端替代不了的)」——桌面 GUI=真 webview(原生能力/hover)、远程浏览器=内嵌远程真实路径或 server 模式(守卫分支/WS resync)、PWA=≤768px+coarse pointer+standalone 模拟(断点边界/触屏/门控能力);附浏览器模拟 PWA 的四条实测坑、桌面零修改像素 diff 验收、server 孤儿进程坑、真机属用户侧动作的边界。
  - **§8 自检清单补一项**:三端矩阵验证 + 单端改动的另两端回归确认。

## 验证

- 纯文档改动,无代码影响,不涉构建/测试。
- 写入的三端差异维度与术语逐条对照既有事实核实,无凭空发明:`window.__mdRemote` / `isRemoteClient()`(`frontend/src/lib/remote.ts`)、`remote:resync` 派发(`internal/remote/customjs.go`)、coarse pointer CDP 模拟 / 像素 diff / 768 断点 / server 孤儿进程 aria `[disabled]`(M2 与 PWA 六件套两条 worklog)。
