# 定时预设三连:chip 独立行 + 60 档 + 显式 Reset + 列表预算 cap(#144/#145/#146,父 #27979 / 任务 #27980)

日期:2026-08-28 | 基线:main = a549710 | 分支:agent/coder/6dca047f

## 起因与原文要点

QueuePanel 定时行的三个体验缺口(GitHub #144/#145/#146,要点经父任务 #27979 复核):

- **#144(布局不变量)**:staged chip(`queue-schedule-pending`)挤在 `.queue-item-actions` 行内(index.css 原 :1534 一带),点击预设后 chip 出现/增长会把行内按钮挤错位。要求:chip 移出 actions 行、独立 `.queue-schedule-staged-row`,窄屏 `flex-basis:100%` 分支同步。**不变量 = 连续点击预设按钮 `getBoundingClientRect` 恒定**。
- **#145(60 档)**:`SCHEDULE_PRESETS` 从 `[5,10,30]` 扩到 `[5,10,30,60]`;累加/24h cap 逻辑零改动;i18n `queue.schedulePreset` 参数化复用,文案「+60 分」不做「+1h」特例;四档宽度桌面单行/窄屏两行均不错位。
- **#146(显式 Reset + 列表预算)**:预设行尾加显式 Reset 按钮,仅 staging 非空显示,复用 chip ✕ 逻辑(resetStagedTime);语义 = 清 staged 回 baseline(base=max(scheduledAt,now) 的既有基线逻辑不动);行宽不够用 ↺ 图标 + md-tip tooltip;i18n zh+en 复用 `queue.scheduleResetTip`。另:列表预算感知滚动上限——复用 #151 预算机制(Composer clampComposerHeight/composerInputBudget 的量测代数),列表 max-height ≤ 预算 40%,composer 52px 下限优先,内部滚动,触控行高 ≥40px(#126B)不破。

硬测试四条:①连续点击位置恒定 ②+60 叠加与 24h 钳制 ③Reset 清 staged 回 baseline + 空态隐藏 ④多条目内滚且 composer 不受挤压。

## 改法

### A. chip 独立行(QueuePanel.tsx + index.css)

- chip 块从 `.queue-item-actions` 内移出,包进独立 `div.queue-schedule-staged-row`,放在 actions 行**之后**(error 之前)。放后面的原因:行尾追加永远不动前面的按钮——首次点击产生 staged 行时预设按钮也不跳(y 方向同样稳定),不变量从第 1 次点击就成立。
- CSS:`.queue-schedule-staged-row { flex-basis:100%; display:flex; align-items:center; min-width:0; }`——全宽度自占一行(桌面/窄屏一致)。窄屏 ≤768px 分支同步:原 `.queue-schedule-error, .queue-schedule-cap, .queue-schedule-pending { flex-basis:100% }` 中移除 `.queue-schedule-pending`(它已在新行里,行本身全宽);error/cap 仍在 actions 行内,保留原规则。chip 内 ✕ 的触控加大规则(`padding:6px`)不变。
- 新增派生量 `stagedVisible = pendingAt !== null && pendingAt > now`(与原 chip 条件逐字一致),chip 行与 Reset 共用。

### B. +60 档(QueuePanel.tsx)

- `SCHEDULE_PRESETS = [5, 10, 30, 60]`。`presetSchedule` 的累加与超 cap 拒绝逻辑**零改动**(超 24h 仍是拒绝并亮 cap 提示,不钳制)。i18n 无改动:`queue.schedulePreset` zh「+{{mins}}分」/ en「+{{mins}}m」对 60 自然成立,无 +1h 特例。

### C. 显式 Reset(QueuePanel.tsx + index.css)

- `.queue-btn.reset`(RotateCcw ↺ 图标,md-tip tooltip + aria-label,复用 `queue.scheduleResetTip` zh+en 既有文案),onClick = `resetStagedTime`(与 chip ✕ 同一 handler:清 pendingAt/cap/error、输入框回默认 now+1min、行不关、不提交)。
- 放 **actions 行最后一个子元素**:`stagedVisible` 条件渲染只影响其身后的空白,几何上不可能移动它之前的任何按钮——这是不变量的结构保障。
- 样式:`.queue-btn.reset { padding:4px 6px }` + hover 变琥珀色;窄屏自动落进 `.queue-btn { min-height:40px; min-width:40px }`(#126B 触控家族,行高不破)。

### D. 列表预算感知滚动上限(QueuePanel.tsx + index.css)

- 结构:queue items 包进新容器 `.queue-list`(header 保持钉住,列表内部滚动);`.queue-panel` 挂 `panelRef`,列表挂 `listRef`。
- 量测(复用 #151 代数,注释内注明):`budget = (window.innerHeight − .chat-body rect.top) − (footer.scrollHeight − list.offsetHeight)`——即 #151 的 `other` 减法,把列表自己放在「被扣除」的位置;**减去自身占位使重算对自身高度不变,天然幂等,不会成环**。`maxHeight = max(round(0.4 × budget), 0)`。
- 触发:`window resize` + ResizeObserver 观察 `.queue-panel`(与 Composer 的 RO 同一目标选择:footer 60vh cap 冻结后 panel 的 box 仍会动);无 `.chat-footer` 祖先(裸挂载/测试)时不观察、不设 cap——与 Composer 裸挂载行为一致。
- 52px 下限优先:composer 的下限由 `clampComposerHeight` 独立保证,列表 cap 不与之对抗;极端小窗(budget ≤ 0)时列表 cap 到 0,由 #151 的 `.chat-footer { max-height:60vh; overflow-y:auto }` 兜底滚动,send/stop 仍可达。
- CSS:`.queue-list { display:flex; flex-direction:column; gap:5px; min-height:0; overflow-y:auto; }`——与原 `.queue-panel` 的 item 间距节奏一致(纯容器变化,行高/触控目标不动)。

## 验证

### 硬测试四条(全部自动化通过)

2. **+60 叠加与 24h 钳制**(`schedule-trio` #2/#3):+5+10+30+60 → Save 提交 ≈ now+105min(±1min 容差);+60 按钮文案 = 参数化 `queue.schedulePreset:mins=60`(无 +1h 特例);seed 23h55m 时点 +60 → 被拒绝:cap 提示出现、chip 冻结在 mins=1435、Save 提交值 = 未动过的 seed(拒绝值绝不泄漏进提交)。
3. **Reset 清 staged 回 baseline + 空态隐藏**(`schedule-trio` #4):空 staging 时 Reset/staged 行/chip 三者都不渲染;+5+10 后三者齐现;点 Reset → 不提交、行不关、三者全消、输入框回默认 ~now+1min;随后 +5 → Save ≈ now+5min(基线 seeding 逻辑未被 Reset 改动)。

## 决策记录

- **staged 行放 actions 行之后而非输入框之下**:行尾追加在首次点击时也不移动预设按钮(不变量从第 1 次点击即成立);放在输入框之下会让首次点击把 actions 行顶下去一行。
- **Reset 复用 `resetStagedTime` 原样**,不改 baseline seeding(任务明示「复用 chip ✕ 逻辑」「base 不动」);对带未来 scheduledAt 的项,Reset 后预设从 now 重累加(chip ✕ 的既有语义,i18n 文案本就如此写明)。
- **极端档列表 cap 到 0 而非设最小高度**:严格执行「≤ 预算 40%」,可达性交给 #151 已验证的 footer 兜底滚动;自造列表下限会在极端档与 composer 抢空间。
- **fake 流模型代替真实 rect 断言**:happy-dom 无排版引擎,零值 rect 断言是空洞的;假模型 + 结构断言(行外/行尾)联合锁定不变量的根因,与 #151 测试的 fake geometry 套路一致。
