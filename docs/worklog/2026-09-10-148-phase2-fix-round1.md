## 改法

- **Fix 1**:`QueuePanel.tsx` onDragOver 首行恢复 `if (!dragId) return;`(+英文注释
  说明语义:无内部拖拽=外部拖拽,不高亮不放行)。内部 reorder 不受影响(dragstart
  同步 flush 在先,dragId 已置位)。新增回归测试:无 dragstart 的 dragover →
  `preventDefault` 不被调用(spy 断言 `prevented===false`)+ 行不加 `drag-over` 类 +
  onReorder 若被调直接 throw。
- **Fix 2**:Esc effect 补 `return () => document.removeEventListener("keydown", onKey);`。
  新增泄漏测试:spy 包裹 document 的 add/removeEventListener 计 keydown 净注册数,
  断言 关闭态=0 / 开启态=1 / Esc 关闭后=0 / 重开后=1 / 开启态 unmount 后=0
  (close 与 unmount 两条泄漏路径都钉死)。
- **Fix 3**:chip 改为 `data-tooltip-content={t("composer.cfgChipTip")}`(reviewer
  首选:语义「点按切换模型/模式/思考」贴 sheet 入口;`data-tooltip-id="md-tip"`
  锚点保留,react-tooltip 机制本就存在)。新增消费测试:i18n mock 返回 key 原文,
  断言属性值===`"composer.cfgChipTip"` 且 ≠ 旧拼接键,再读真实 zh/en locale JSON
  断言两语言都有非空文案(zh+en 消费在案)。

### 踩坑(新测试价值的现场实证)

改 Fix 3 时一次 edit 工具错位把 `data-tooltip-id="md-tip"` 从 chip 上弄丢了
(工作区瞬时状态,未进 commit)——**正是新增的 cfgChipTip 消费测试当场抓住**
(`data-tooltip-id` 断言 received null),否则 react-tooltip 无锚点、tooltip 静默
失效。已补回。这单是「字段加了没人测=回归无声」的又一实例。
