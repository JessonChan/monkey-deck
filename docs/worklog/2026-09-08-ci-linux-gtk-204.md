# 2026-09-08 #204 CI Linux GTK 依赖

## 起因 / 根因(#203 修复后暴露的第二层)

- #203 的 stub 只解掉 embed 这第一道闸;stub 落地后,backend job linux 腿的
  `go build .`(GOOS=linux)第一次真正进入 wails v3.0.0-alpha2.106 的 Linux
  后端:`pkg/application` 的 `pointer` 仅定义于 `linux_cgo.go`
  (`//go:build linux && cgo && !gtk3 && !android && !server`,
  `#cgo linux pkg-config: gtk4 webkitgtk-6.0`)→ CGO 路径必经。
- ubuntu-24.04 runner 未装 GTK4 / WebKitGTK dev 头 → CGO 编译必炸
  (#203 两份 worklog 已独立交叉实证过这一层,本卡即修它)。
- 附带:ci.yml 原 54-55 行注释「CI 仅验证 Go 编译(不 CGO)」对当前 wails
  版本不成立(linux 腿现在就是真 CGO 编译),一并修正;触及的旧中文注释
  按规范转英文(AGENTS.md §3.7)。

## 改法决策:方案 A,方案 B 实证否决

- **方案 B(备选)本机复跑否决**:stub 态下
  `GOOS=linux CGO_ENABLED=0 go build -o /dev/null .` → rc=1,
  `undefined: pointer`(wails `menu_linux.go:7`、`menuitem_linux.go:12,14`、
  `webview_window_linux.go:31-42` 等)——wails v3 根包**不存在**纯 Go linux
  编译面,B 的前提(纯 Go 可编译)不成立。与 #203 实现/review 两份 worklog
  的独立结论一致。→ 采用拍板推荐的方案 A。
- **方案 A(主)**:backend job 增 linux-only 依赖安装步骤,置于 Build
  backend 之前。单步 + `if: matrix.goos == 'linux'`(任务给出的首选形态,
  三平台矩阵语义不变;不采用 matrix include 拆分)。步骤顺序取 release.yml
  同款块写法(`apt-get update` 与 `apt-get install` 两行)。
- 包列表 = release.yml:133-136(`libgtk-4-dev libwebkitgtk-6.0-dev`)的
  **超集**:显式加 `libsoup-3.0-dev libglib2.0-dev`;语义一致,传递依赖由
  apt 自解析。runner 自带 gcc / pkg-config,dev 包提供 `.pc` 文件即可。
- 安装步在 Build / Vet / Test compile 之前 → linux 腿的
  `go vet ./internal/...` 与 `go test -run xxx_none`(原生 GOOS=linux)同样
  吃到头文件(若 internal 包链到 wails 也不缺)。
