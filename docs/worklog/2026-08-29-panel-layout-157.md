# #157 面板布局修复:popout 退出布局持久化 + 折叠态仅主窗持久

- **日期**: 2026-08-29
- **issue**: #157(规格:父 issue #28388;注意父 issue 文本因 shell 转义丢了 localStorage key 名,以任务 desc 为准)
- **基线**: main = `434f5b5`
- **类型**: fix(frontend) + mount 测试

## 起因

popout 窗口(session 独立窗口)与主窗口共用同一份布局持久化:

- `App.tsx` 挂 `useDefaultLayout({ id: "monkey-deck-layout", onlySaveAfterUserInteractions: true })`,**不区分 isPopout**。
- Wails 同源多窗口共享 localStorage。react-resizable-panels v4 的 `useDefaultLayout` 默认 storage 就是全局 `localStorage`,实际落盘 key 由 id 派生:**`react-resizable-panels:monkey-deck-layout`**(源码:`react-resizable-panels:${[id, ...panelIds].join(":")}`,不传 panelIds 即此值)。
- popout 的面板结构与主窗不同(无 `sidebar` 面板):popout 里拖拽分隔条(用户交互,`onlySaveAfterUserInteractions` 不拦)会用 popout 的布局**覆盖主窗存档**;popout mount 时还会**读走**主窗存档。主窗重启即恢复出错误布局。
- 同时,左右面板的折叠态(`leftCollapsed`/`rightCollapsed`)从未持久化——重启后折叠丢失;而 `onlySaveAfterUserInteractions` 语义上本来就不存按钮 collapse(命令式调用被过滤),折叠态需要独立持久化。

## 根因

持久化边界按「窗口」而非「主窗/popout」区分。popout 是临时视图,结构不同、生命周期不同,根本不该进主窗布局存档;折叠态则是主窗 UI 状态,缺一条自己的持久化通道。

## 改法(全部在 `frontend/src/App.tsx`)

### ① popout 完全退出主布局持久化

```ts
const { defaultLayout, onLayoutChanged } = useDefaultLayout({
  id: "monkey-deck-layout",
  onlySaveAfterUserInteractions: true,
  storage: isPopout ? NOOP_LAYOUT_STORAGE : undefined,
});
```

- `NOOP_LAYOUT_STORAGE: LayoutStorage = { getItem: () => null, setItem: () => {} }`(lib 导出类型 `Pick<Storage, "getItem" | "setItem">`)。
- hook 无条件调用(hooks 规则),popout 经 noop storage 达成规格要求的 **defaultLayout=undefined(getItem 恒 null)+ onLayoutChanged 写丢弃**;**不新增 popout 专属持久化**,popout 维持默认(右侧收起 mount collapse / 左侧本就不渲染)。
- 为什么不用「isPopout 时换返回值」的写法:那样 hook 仍会真读真写主窗 key,不满足「不读不写」。

### ② 折叠态仅主窗持久化

- 新 key 字面量 **`md:panel-collapsed`**(冒号小写),值为 JSON `{"left":bool,"right":bool}`;`readPanelCollapsed()` 容错解析(缺省/坏 JSON/形状不对 → 全展开),对齐 `Sidebar` expanded-set 的容错惯例。
- **写点** = 新 effect,依赖 `[isPopout, leftCollapsed, rightCollapsed]`,`isPopout` 直接 return(popout 不读不写);best-effort try/catch(同 fontScale/notifySound 等既有 `md:*` key 惯例)。
- **读点** = 既有窄窗 effect(750px auto-collapse 所在 effect)的主窗分支,mount 走既有 imperative `collapse()` 复载(与 popout 右侧 mount collapse 同一条路径)。**尊重 App.tsx M2 抽屉竞态注记(原 2082 行):已知手机端库的延迟初始布局可能静默覆盖 mount collapse,刻意不为它新开机制**;桌面窗口恢复可靠。
- 已知无害瞬态:mount commit 先写 `false/false`,restore collapse 触发 onResize → setState 后重渲染覆盖为恢复值,终值恒正确。

### ③ 窄窗 750px auto-collapse 不变

原分支原样保留(测试覆盖:600px 视口 mount 自动收起不受影响)。

## 键位矩阵(改后)

| key | 谁读 | 谁写 | 内容 |
|---|---|---|---|
| `react-resizable-panels:monkey-deck-layout` | 主窗 mount(经真实 hook → defaultLayout) | 主窗拖拽保存(`isUserInteraction:true` 才落盘) | 面板尺寸 JSON |
| 同上 | popout **不读**(storage=noop) | popout **不写** | — |
| `md:panel-collapsed`(新) | 主窗 mount(`readPanelCollapsed` → imperative `collapse()` 复载) | 主窗折叠态变更 effect | `{"left":bool,"right":bool}` |
| 同上 | popout **不读** | popout **不写** | — |

## Popout 隔离证明(测试实证,非推理)

`frontend/src/App.panel-collapse.mount.test.tsx`:mock 掉 Group/Panel/Separator/usePanelRef(happy-dom 无布局引擎),**useDefaultLayout 用真库**(只有真 hook 才能让 App 传入的 noop storage 生效可见),localStorage 换成带访问记录的 Map fake(happy-dom 的 Storage 实例方法无法 spy——赋值被静默忽略,实测)。popout 用例:

1. **不读**:预置**有效** layout(全数字值,真 hook 读到就会还原为 defaultLayout)→ popout mount 后 `defaultLayout === undefined`。
2. **不写布局 key**:popout 内驱动 `onLayoutChanged({...}, {isUserInteraction:true})`(真 hook 的立即保存路径)→ 存档原值不变。
3. **不写折叠 key**:popout 内 expand/collapse 点击(主窗写点的触发路径)→ `md:panel-collapsed` 始终不存在。
4. **spy 全扫**:getItem/setItem 记录中无任何含 `monkey-deck-layout` 的 key、无 `md:panel-collapsed`。
5. **对照组**:主窗同种子 → defaultLayout 还原为种子对象、布局保存落盘、折叠点击逐值落盘(`left`/`right` 四个断言)。

另覆盖:种子 `{"left":true,"right":false}` → mount 恢复走 imperative `collapse()`(mock handle 记录到调用)+ `data-sidebar-collapsed="true"`;二次 mount(reload 模拟)幂等恢复;`{"left":false,"right":true}` 右侧变体;坏 JSON 不崩、回退全展开;600px 窄窗 mount 自动收起不变。
