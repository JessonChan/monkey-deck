# 2026-07-28 AGENTS.md 新增「代码注释默认使用英文」硬约束

## 起因

用户要求:以后新增的注释默认用英文;旧中文注释在「被修改/触及」时也要顺手从中文转成英文。属于代码风格 / 写代码纪律,需落到 AGENTS.md 作为硬约束(§6.1「文档先于代码」)。

## 决策

- 归类为 **§3 实现纪律（写代码时）** 下的新 **§3.6**,与「写代码时该怎么做」同章节。
- **仅约束源码注释**(`//` / `/* */` / `--` 等)。**文档文件**(AGENTS.md、`docs/worklog/*`、README、THIRD_PARTY_LICENSES)**仍用中文**——这些是给人读的项目文档,跟代码注释是两回事,不混为一谈。
- **旧中文注释采用「触及即转」的渐进迁移**,不要求一次性全仓翻译(全仓翻译既不现实、也会污染 git blame、违背 §6.2「不夹带无关改动」);但「碰到就要顺手转」,避免新旧风格长期共存。
- commit message 规范仍在 §6.2,本次不扩展到 commit message(避免越界用户原意)。
- 理由:标识符 / API / 依赖库文档都是英文,注释用英文保持一致,利于检索、跨语言协作与 AI 工具处理。

## 改法

1. §3.5 后新增 §3.6「代码注释默认使用英文(硬约束)」,4 条:新增一律英文 / 旧注释触及即转 / 仅限源码注释(文档仍中文)/ 理由。
2. §8 自检清单补一条:`- [ ] 新增代码注释用英文;本次改动触及的旧中文注释已转英文?(§3.6)`,放在 git/commit 检查项之后。

- 纯文档改动,无代码 / 测试影响。

## 下一步

- 该约束即日起生效。后续所有改代码的 agent 应遵守:新增注释写英文、触及的中文注释转英文。
- 不主动发起全仓中文注释翻译(违背「触及即转」的渐进原则 + §6.2 不夹带)。
