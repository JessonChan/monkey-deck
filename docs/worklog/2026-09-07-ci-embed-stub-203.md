# 2026-09-07 #203 CI embed stub

## 起因 / 根因(已核实)

- `main.go:22` `//go:embed all:frontend/dist` 要求编译期 `frontend/dist` 存在,
  但 dist 是构建产物,git 不含 → CI backend job(checkout 后直接 `go build . ./internal/...`)
  在三平台矩阵(darwin-arm64 / linux-amd64 / windows-amd64)上**embed 模式必炸**。
- 实证:本 worktree checkout 态本来就没有 `frontend/dist`,直接复现——
  不建 stub 时 `go build .` 报 embed 无匹配文件;建 stub 后即过。
- 另一个 embed 指令 `internal/store/store.go:14`(`migrations/*.sql`)引用的是
  入库文件,checkout 自带,不是缺口。

## 改法(主案,KISS,单步 stub)

backend job 的 steps 在 `actions/setup-go` 之后、`Build backend` 之前插入单步:

```yaml
- name: Stub frontend/dist (go:embed needs the dir)
  shell: bash
  run: mkdir -p frontend/dist && echo stub > frontend/dist/index.html
```

- `shell: bash` 三平台 runner 均内置(GitHub windows-latest 含 Git Bash,
  官方文档明确 `shell: bash` 落到 Git Bash),`mkdir -p` + `echo >` 全兼容,
  **单步全覆盖,不需要 pwsh 备选**(`New-Item`/`Set-Content` 等价方案未采用)。
- embed 对 stub 内容无额外要求(`all:` 前缀只影响 `_`/`.` 开头文件的可见性,
  目录非空即可),故**不采用 build-tag 双文件备选**。
- 新增注释英文(§3.7);紧邻的既有中文注释行未触及,保持原样(diff 最小)。

## 改了哪些文件

- `.github/workflows/ci.yml` —— 仅 backend job 插入 3 行注释 + 3 行 step;
  frontend job、release.yml、main.go 嵌入指令**零改动**(红线全守住)。
- 本 worklog。

## 验证(全部本机复跑,2026-09-07)

- **① stub 态可编译**:dist 删除态(= checkout 态)→ 按新 step 逐字执行
  `mkdir -p frontend/dist && echo stub > frontend/dist/index.html` →
  `GOOS=darwin GOARCH=arm64 go build . ./internal/...` **过**(= 矩阵 darwin 腿,
  GOOS 变体抽验 ≥1 达标;link 期 ld warning 为本机 SDK 版本噪声,非错误)。
- **② 真实产物照旧**:`bun install` + `wails3 task bindings` + `bun run build`
  还原真实 dist(本 worktree 曾被重置,bindings/dist 均需重建)→
  `go build .` **过**(embed 吃到真实 index.html/assets)。
- **③ 红线零 diff**:`git status` 仅 `.github/workflows/ci.yml` modified;
  release.yml / frontend job / main.go 无改动。
- **④ 零回归**:`go test -run xxx_none ./internal/...` 15 packages ok(编译过);
  `go vet ./internal/...` 过。
- YAML 结构核验:backend steps 顺序 = checkout → setup-go → Stub → Build →
  Vet → Test compile。

## 重要留人情报:stub 之后 linux/windows 腿有**下一层**失败(本卡范围外)

stub 只解除 embed 这第一道闸(它此前对三条腿都是最先爆的)。本地交叉编译
实证,另两条腿在 Build backend 还有**先于本卡存在**的平台缺口:

- **windows-amd64 腿**:`internal/terminal/service.go:286-287`
  (`syscall.Getpgid`/`syscall.Kill`)与 `internal/acp/proc.go:47,68,74,80,367`
  (`SysProcAttr.Setpgid`/`syscall.Kill`)无 build-tag 拆分,windows syscall
  无这些符号 → `GOOS=windows go build . ./internal/...` **编不过**(本机实证)。
  CI windows 腿过 stub 后会在此爆。
- **linux-amd64 腿**:wails v3 alpha2.106 的 `pkg/application` 中 `pointer`
  仅定义于 `linux_cgo.go`(`//go:build linux && cgo && !gtk3 && !android &&
  !server`;`#cgo linux pkg-config: gtk4 webkitgtk-6.0`)→ **无 cgo 必炸**
  (`undefined: pointer`,本机交叉实证,CGO 自动关);有 cgo 则要 gtk4/
  webkitgtk-6.0 dev 头,ci.yml 未装(release.yml 才装齐)。即 ci.yml 既有注释
  「CI 仅验证 Go 编译(不 CGO)」对当前 wails 版本**不成立**,linux 腿过 stub
  后仍会在此爆。
- 两者均非本卡改动引入,也不属本卡「ci.yml 单文件」改动面;按红线不动
  Go 代码。修法方向(另卡):windows 腿补 syscall 平台拆分文件;linux 腿
  要么装 dev 头走 CGO、要么 wails 出无 cgo 的 linux 编译面(或 linux 腿
  改为仅 `go vet`/test-compile 不 `go build .`)。
